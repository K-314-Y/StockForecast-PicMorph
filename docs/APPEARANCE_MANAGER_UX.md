# 仮版：外見マネージャー UX（Sprint 89）

## 目的

「元の外見に戻す」という曖昧な表現をなくし、今ゲームに表示している外見と、切り替え先を区別する。以前のイラスト保存を巻き戻す機能ではない。

## UI

- 外見スタジオの先頭に「今ゲームに表示中」と明示する。
- 2択を常に表示：**自分の外見**（従来のイラスト、髪色、髪型、カスタムchibi）と **登録したキャラ**（MCPで登録した手続き描画キャラ）。
- 「自分の外見を表示」では既存の見た目の表示レイヤーに戻すだけ。元画像・名前・髪色・AI予測設定を復元や削除しない。
- 「このキャラに切り替える」は明示的クリックでのみ保存。プルダウン選択のみでは保存しない。別タブ競合なら従来の 409 対応を維持する。
- 切替後は現在の表示名とカード内の「表示中」を変更し、上のゲーム画面へ飛べるリンクを用意。
- 登録キャラ表示中、下の「自分の外見」用の髪色・髪型・イラスト編集がその表示画像を変えないことを明示する。
- 外見スタジオ起動時は詳細な髪型編集とイラスト編集を自動展開しない。編集はユーザーがその詳細欄を開いたときに行う。
- 560px以下は2択を縦に並べる。動きを減らす設定、キーボード操作、44px以上のボタンを維持する。

## データ・非対象

既存の game_runtime/generated-avatar.mjs のリビジョン付き POST /api/active-character のみを再利用。保存済みイラスト/Look/Companion/予測/XP は変更しない。今回の仮版はキャラの削除・名前変更・ドラッグ並べ替え・サムネイル一覧・正式なモデル結合までは実装しない。

## 検証

ローカル Chrome Playwright で320px/1280pxの配置、明示的選択、再読込、解除、保存への意図しない POST がないこと、横スクロールなし、JSエラーなしをテストする。

参照：導入済み Modern Web Guidance の forms・form-factor-adaptation・accessibility のガイド。選択メニューの変更だけで保存しない、ネイティブの fieldset・legend と操作状態の文字表示を使う。


## 登録ボタンの場所（Sprint 91）

Linuxのゲーム /game → 「外見を選ぶ・作る」 → 「登録したキャラ」 →
「＋ 新しいキャラを作って登録」を開く。名前・髪色・服色・飾りを指定して
「キャラを生成して登録」を押す。ローカルでオリジナル図形の6コマPNGを作り、
登録済みの一覧に追加する。**登録だけではキャラの表示は切り替わらない**。
ゲームで使うときは「このキャラに切り替える」を押す。

Windowsプレビューでは登録ボタンは無効で、Linuxで作る案内が表示される。
両PCの保存画像はまだ同期されない。登録処理のPOSTは同一PCのlocalhostのみ、
入力サイズと色・名前を制限し、株価予測・XP・イラスト保存には触れない。


## PNGパーツのドラッグ＆ドロップ登録（Sprint 92）

**優先入口**：Linuxゲーム /game → 画面上部の「PNG・ZIPをドラッグ＆ドロップして登録する」。
これを押すと外見スタジオの登録欄まで直接スクロールする。
既存の body / ready / happy / cautious の4枚（PNG/WebP）か4枚入りのZIPをドロップし、
キャラの名前を入力する。プレビュー確認後に **「このPNGキャラを登録する」** を押して登録。
名前で4枚を判別するので、ファイル名には各パーツの英字を含める必要がある。
横6コマ、3列×2行、単一静止画をブラウザ内で標準の横6コマPNGへ変換する。
顔の背景には透明部分が必要。個別の元画像は上書きしない。

登録後に一覧へ自動反映するがゲーム外見は変更しない。
使うときだけ従来の「このキャラに切り替える」を押す。
「PNGパーツ実験室」はプレビュー専用で、そこからゲームへの保存は行わない。
従来の図形テンプレート生成は別機能に変更し、優先表示しない。
Windowsの確認用コピーは同じフォームを見ることができるが、
LinuxのプライベートPNGファイルと保存状態は同期せず、登録機能は無効。


## 用意済みパーツと組み合わせ（Sprint 92 追加）

PNGパーツの入口で **「用意済みのHatchPet画像パーツを試す」** を押すと、
もともとプロジェクトに入っている透明WebP（体・通常顔・笑顔・心配顔）を
自動的に読み込む。元画像を変更せず、登録時に6コマPNGへ変換する。
また、「体・表情・髪・服を個別に選ぶ」を開くと、ユーザーが用意済みの
PNG/WebPを役割ごとに指定して重ねられる。髪・服は6コマでも1枚の静止画像
でもよく、静止画像は全6コマに繰り返す。ZIPにも髪・服の追加を認識する。

髪・服の重なり順：体 → 服 → 表情 → 髪。登録データとしては体と表情3種の
横6コマPNGへ合成して保存する。現在は既存のHatchPet素材1組を同梱した
仮版であり、複数の異なる髪型・衣装を備えた本格的なパーツ図鑑ではない。
キャラの見た目の精度そのものは今後専用の作画素材で改善する必要がある。
