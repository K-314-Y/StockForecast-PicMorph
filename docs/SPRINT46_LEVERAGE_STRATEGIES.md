# Sprint46 架空相場・10連戦の倍率政策比較

指定3ファイルだけで完結する独立CLI。ゲーム本体への接続はない。本物のAIではない、実資産非連動、期待値の証明ではない。未来株価予測やモデル賢さランキングを実装したものではない。

```bash
node scripts/sprint46_leverage_strategies.mjs
node scripts/sprint46_leverage_strategies.mjs --seed 46 --samples 20 --refill compare
node scripts/sprint46_leverage_strategies.mjs --seed 46 --samples 200 --refill compare
node scripts/sprint46_leverage_strategies.mjs --seed 2026 --samples 200 --refill compare
node --test mcp/tests/sprint46_leverage_strategies.test.mjs mcp/tests/sprint45_highrisk_lab.test.mjs mcp/tests/leverage-practice.test.mjs
git diff --check
```

既定はseed=46、20群、給付off。seedは整数0〜4294967295、samplesは整数1〜1000。給付はoff/on/compare。未知・重複・欠落引数はエラー。結果・ヘルプ・エラーは標準出力のみ、失敗時終了コード1。ファイル保存・通信・サービス操作は行わない。

## 比較条件と情報の境界

初期3,000 C、12ステップ×10戦、投入比率10%/50%/100%。Sprint45の `makeScenarios(seed, samples)` と `makePlan(scenario, amount)` を再利用し、すべての政策・投入比率・給付条件に同じ架空価格・売買シグナルを使用する。生成器は各価格変化を抽選する前にLONG/CASHを決定する。学習や外部予測はない。手数料0.1%、mine配分100%、リスク比率1。

| 政策 | 戦の開始時に確定する倍率 |
| --- | --- |
| fixed5 | 常に5倍 |
| fixed25 | 常に25倍 |
| hot25 | 直前に完了した2戦の倍率なし基準収益が両方プラスなら25倍、それ以外5倍 |
| protect | 今の財布が過去の日次財布最高額の70%未満なら1倍、それ以外10倍 |

hot25は過去好調という条件であり、未来の予測力ではない。0利益は好調に含めない。最初の2戦は5倍。protectの70%ちょうどは10倍。最高額は初期財布・日次財布・給付後財布を含む。給付があれば加算後の財布で選択するため、給付で再び高倍率になる場合もある。

倍率なし基準収益（AI予測精度とは別）は、毎戦独立した固定1,000 Cを1倍で決済した純利益。政策の実財布・実投入・選択倍率とは独立で、全政策共通。同じシグナルの収益を見るものであり、方向予測の的中率やモデル間の賢さ評価ではない。`runSyntheticGame` と `settleLeveragedPractice` を実投入と基準収益の双方に使用する。

政策関数 `chooseLeverage` は純粋関数。`makeSnapshot` が作る凍結済みの財布・過去最高額・完了済み基準収益配列だけを受け取り、価格・シグナル・scenario・現在結果を受け取らない。配列はコピーして凍結する。余分なフィールドは拒否する。現在戦のscenario参照を取り出す前に倍率を確定する。基準収益の記録は戦の決済終了後で、次戦以降だけが利用する。投入0でスキップした戦も、終了後に公開された仮想経路として観測する。未来を見て最適倍率を選ぶベンチマークはない。

## 会計と集計

投入は `floor(floor(wallet) * ratio)`。整数未満の端数は保留。投入0はスキップで全損に数えず、日次財布を維持する。給付onのみ、次戦開始時の財布が1 C未満なら3,000 Cを加算し端数保持。0.63 Cなら3,000.63 Cから再開し、全額投入は3,000 C。1 Cちょうどは給付しない。最後の戦の後には給付しない。

純損益 = 最終財布 − 初期3,000 C − 発行給付全額。給付は利益ではない。投入以外の現金は保持、投入全損後はその戦内で復活しない、借金なし、最大25倍。利益上限・実XP・シーズン制は追加しない。

Sprint45と同じ順序でセント丸めを行う。既存シミュレーターの投入上限1e9や安全な整数・セント表現範囲を超えた場合は、利益を切り詰めず実験をエラー終了する。比較結果を途中まで正常な表として出さない。固定5/25についてSprint45 `runChain` とすべての会計フィールド・戦ごとの日次財布が一致するテストがある。

平均・中央値は独立した10連戦の最終財布と給付控除後純損益から算出。全損率は投入全損戦数/実行戦数、実行率は実行戦数/(10×群数)。25倍選択頻度はスキップも含む全戦での選択率。不能群は一度でも財布1 C未満となった連鎖数（厳密ゼロを含む）。厳密ゼロ群も別掲。比率を掛けた投入が0になることと財布1未満は異なる条件。

最大下落率は給付前の全損も含む日次財布の過去最高からの下落率を連鎖ごとに計算し、表には全群での最大を表示する。給付は損失を相殺しないが、最高財布には影響する。要約には平均・総給付と総給付回数も保持し、CLIには平均・総給付控除額を表示する。先頭群の各戦の倍率・給付・投入・損益・基準収益・日次財布も出力する。

## 判断と弱点

1〜25倍の大勝負は維持する。今回の実験だけでhot25/protectを自動推奨の標準政策にする根拠は弱い。まずゲーム内の任意選択候補として検討する程度が妥当で、実装したのは比較CLIまでである。

- fixed25の10%投入は200群両seedで実行率100%、平均純損益+514.50/+308.52 C。ただし中央値は−121.75/−140.75 C、投入全損率61.25/62.75%、最悪下落67.05/68.43%。大勝負と継続性の候補にはなるが、常勝・公平・収益の保証ではない。50%投入は平均が正でも中央値−2,593.87/−2,698.25 C、下落は約100%。
- hot25の10%投入は20群seed46では平均+172.01 Cだったが、200群ではseed46で+12.37、seed2026で−79.93 C。中央値も両seedで負。50%投入の平均も+377.84から−532.65 Cに変わる。過去好調条件を予測力と呼べない。25倍選択率18/16.3%なので、常時25倍に比べ大勝負の頻度も減る。
- protectの50%投入は最悪下落73.79/72.34%でfixed5の94.12/95.82%より小さい一方、平均純損益は+369.54/−465.54 C、中央値は両方負。下落後の縮小が収益改善を保証しない。全額投入では最初の10倍などで一気に全損し得て、不能群50.5/52.5%。安全政策という名前で安心させるべきではない。25倍の大勝負自体も選ばない。
- fixed5・10%投入は平均純損益−52.77/−106.03 Cだが、最悪下落38.46/40.62%、実行率100%。比較の基準として意味がある。全額投入にするとfixed5ですら不能群22/22.5%。倍率だけでなく投入比率が継続性を大きく左右する。
- fixed25・全額投入は給付なしで両seed全200群が財布1 C未満。給付ありでは平均財布8,500.77/12,239.96 Cに見えるが、総発行330.3万/335.7万 Cを控除すると平均純損益−11,014.23/−7,545.04 C。給付による試行継続とバランス維持は別問題。

平均は少数の大勝ちに大きく左右される。選んだseed・生成器・手数料・日次決済・10戦という短い期間に依存し、価格のトレンドや相関構造も網羅しない。低い投入全損率だけで優良政策とは言えない。ゲームの面白さはこの数値から直接測れず、体験評価は未実施。勝利確率を現実相場・外部世界へ一般化しない。
