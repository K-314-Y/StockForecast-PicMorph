# 実市場データへの接続条件（P8）

**実市場への移行は権利確認待ちで停止中です。** ユーザーが適用可能なライセンスを保有しているかは未確認です。ゲームは既定で実市場未接続です。P7 はサーバー内部で検証した署名付き架空データ（`MOCK_NONLIVE`）だけを使い、予測を `TEST_ONLY` として保存します。

## 提供元の確認メモ（2026-11-19）

- J-Quants 無料プランは12週間遅延します。過去相場の練習と、対象時刻の実市場観測による先出し予測の採点は別用途です。[J-Quants プラン](https://jpx-jquants.com/ja/help/plan)
- J-Quants 利用規約第8条は私的使用に範囲を限定しています。第三者利用、配信、商用利用、学術利用は対象外です。ゲームの公開前に用途に応じた別途許諾を確認します。[J-Quants 利用規約](https://jpx-jquants.com/ja/termsofservice?lang=ja)
- Yahoo!ファイナンス掲載情報のスクレイピング等による自動取得や再配布は禁止されています。[Yahoo!ファイナンスのヘルプ](https://support.yahoo-net.jp/PccFinance/s/article/H000011276)

## 接続を許可する前に確認すること

1. **権利と保管**。提供元の書面で対象データ、ゲーム内での利用範囲、再配布・公開、多人数利用、原文および履歴の保存期間、解約時の削除義務を確認する。運用担当が契約の対象と実際の構成を照合する。コード上の文字列やフラグで書面の真正性や許諾の有効性は判定できない。
2. **鮮度と取引区分**。対象市場・銘柄、取引価格の区分、更新頻度、許容遅延を決める。取引日時と公表日時を別々に検証し、署名等で出典と内容を確認する。休場・個別銘柄停止、欠測、遅延、重複や順序逆転では、予測・約定・採点を進めない条件をテストする。
3. **接続と停止**。提供元の設定と API キーはサーバー管理とし、キーは専用の秘密情報保管先に置く。ブラウザから接続元・価格・許諾・稼働モードを設定できないようにする。利用期限の終了や検証失敗で接続を停止し、契約に沿って保存済みデータを削除できることを確認する。

## P9 身内向けリアル相場ゲームの構成案（2026-11-19、設計のみ）

Gemini Web版との設計レビュー後、公式のデータ利用条件も照合してまとめた案。**この章は実装・利用許可の完了を意味しない。** P8の `MOCK_NONLIVE` と `TEST_ONLY` の厳格な境界を維持する。開発は既存の `dev/forward-game` だけで行う。

### 開始方針

- **株式優先**。開発者本人の実株価フィード試験候補は Alpaca Basic の IEX リアルタイム米国株。IEXは全米取引の一部なので「全米の正式な株価」「全米リアルタイム統合値」と表示しない。対象銘柄で約定が無い場合は予測・採点を保留する。無料APIを取得できることと、友達に表示・採点結果を配信する許可は別問題。
- TradingView公式ウィジェットは許可範囲内で独立した**閲覧用**。ウィジェット内部の値を読み取って予測・採点・学習する経路を作らない。表示チャートの数値をゲームの約定価格と同一視しない。
- 暗号資産は24時間取引できる予備案。CoinGecko無料Demo APIに商用利用権は含まれない。暗号資産を採用する場合も当該データ源の公開・加工・保持・再配布の権利を別途確認する。
- **許諾未確認の招待制公開**では実市場由来の価格APIや自動採点を無効化し、友人には `MOCK_NONLIVE` の練習だけを開放する。友達5人でも第三者提供になる可能性がある。

### 部品を分離する（現在のコードに上乗せする設計）

1. **価格データの入口（MarketFeedAdapter）**：提供元APIで受けた価格を `symbol / venue / provider / tradeAt / publishedAt / receivedAt / price / sourceMode / conditions` に統一。API鍵はサーバーのみが保持し、ブラウザから接続先・価格・権限を指定させない。
2. **市場ルール（MarketSessionPolicy）**：地域別の取引時間・祝日・夏時間・時間外取引・約定区分を担当。プロバイダーの入れ替えと市場ルールの変更は別にテストする。
3. **検証と観測の記録**：価格>0、時刻逆行なし、予測時点で未公表のデータなし、適切な取引区分と鮮度、十分な約定数を確認。出典と受信時刻の証拠を添える。原データ保存は契約で許される範囲に限定する。
4. **Python予測→事前確定（Freeze）**：P7の保存済みモデルを使用。銘柄・時刻・予測確率・モデル版・使用データ版を将来価格が出る前に固定。後から更新しない。
5. **仮想決済と採点**：予測より後の適格な価格だけで損益と上昇/横ばい/下落の精度を算出。欠測・遅延・時間外は保留／無効扱いにし、架空値で埋めない。
6. **ゲーム内為替→専用財布**：確定損益のみ0.98〜1.02倍してメダルへ反映。予測確率・実価格・元本・的中率は絶対に補正しない。他AIの財布や未配分メダルに損失を移さず、借金・二重精算を拒否。
7. **画面**：外見作成と予測スタジオを分離したまま、データ出典と `架空練習 / 個人検証 / 許可済み実市場 / 未接続` を明示。成績は予測精度、元の仮想損益、FX込みメダル損益、最大下落率をそれぞれ別表示。

### 第一候補のゲームルール（仮決定、未検証）

- 最初は**米国株の通常取引時間のみ／60分先の上昇・横ばい・下落**で試験する。取引終了まで60分以上ないラウンドは開始しない。時刻は米国市場の夏時間・休場に対応する。日本時間で固定の市場時刻を作らない。
- 直近の連続した5分単位の価格履歴を必要数取得し、保存モデルの長期窓（現在既定9）の入力を満たさない場合は予測しない。IEXに約定が無い区間は無理に補完しない。
- 上昇／横ばい／下落のしきい値は**ラウンド開始前に固定**して履歴へ保存する。数値はバックテストを経て決める。新規銘柄・取引所で同じ値を無検証で使わない。
- 60分後の価格が指定した許容観測時間内に確保できなければ無効扱いとして参加メダルを返す。勝手に以前の終値を流用しない。これは初期案であり、採点品質を見て調整する。

### 独自為替の公平性

- ラウンド開始時にサーバー側で倍率を **0.98 / 0.99 / 1.00 / 1.01 / 1.02** から一度だけ選び、ラウンドIDと共に確定保存。予測締切前に選定の証拠（コミットメント）を記録し、締切後かつ結果判明前に倍率を公開して照合可能にする。再抽選禁止・参加者全員同倍率。
- `rawPnl`（実価格で計算した仮想損益）を先に確定し、`gamePnl = round(rawPnl × fx)` を記録する。プラスもマイナスも同じルールで補正し、損失が確保済み財布額を超える場合は許された最大損失で止め、他の財布から引かない。
- 予測スコア（Brier等）とメダル残高ランキングは別集計。為替の運ではAIの予測能力を高く評価しない。

### 実装順・検証条件

1. P9a：市場ルールと価格データの共通形式を **架空データのみ** で作り、未来情報の混入・時刻逆行・欠測・二重保存を自動テストする。
2. P9b：独自為替をサーバー側で確定→決済時だけ適用し、再起動・同じ取引の再送・資金上限・監査のテストを追加する。
3. P9c：開発者本人の隔離された実IEXデータを使い価格受信と精度を試験する。利用範囲を確認するまで公開側に転送しない。
4. P9d：友人5〜10人の招待・個別財布・結果画面を整備。実市場の表示・採点は提供元に確認した許諾条件を満たす場合だけ有効化する。通常の株価表示はTradingView公式埋め込みを別枠として使える。

### Gemini再レビューから採用しない提案（安全性のため）

- Geminiは「翌営業日終値で判定」を提案したが、Alpaca Basic/IEXは全米の公式終値を保証しない。**公式終値の採点を実装済み・利用可能とみなさない**。将来、許諾済み公式終値フィードが得られた場合の日次モードとして別途設計する。個人試験の60分モードはIEX限定の定義を明記する。
- Geminiの「再起動時に期限切れ未確定予測を自動FROZENへ移行」は**不採用**。締切までにサーバーが正しく確定保存した証拠がない予測は失効／無効とする。後出し確定はしない。
- Geminiの「すべての財布に強制的な残高上限を適用」は**不採用**。既存の各AI専用財布の損失上限を守りつつ、利益を上限で突然没収しない。損失のための担保・投入額は注文時に確保し、残高を0未満にできない。
- Geminiの新しい `src/domain/*` 階層を一括導入する案も採用しない。既存 `game_runtime/forward-*.mjs` を維持し、必要な市場カレンダーと権限判断だけを小さく拡張する。
- ゲーム内FXを「予測終了後に事後決定」しない。ラウンド開始前の確定証拠を残し、締切後に公開・照合する（結果判明後の引き直し禁止）。

**未確定事項**：予測方向の横ばい幅、60分後の価格採用期限、銘柄ごとのIEXデータ量、友達への実市場由来の結果公開権。実装前に実データの品質と規約を再点検する。
