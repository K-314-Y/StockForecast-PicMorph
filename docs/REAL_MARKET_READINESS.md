## 接続を許可する前に確認すること

1. **権利と保管**。提供元の書面で対象データ、ゲーム内での利用範囲、再配布・公開、多人数利用、原文および履歴の保存期間、解約時の削除義務を確認する。運用担当が契約の対象と実際の構成を照合する。コード上の文字列やフラグで書面の真正性や許諾の有効性は判定できない。
2. **鮮度と取引区分**。対象市場・銘柄、取引価格の区分、更新頻度、許容遅延を決める。取引日時と公表日時を別々に検証し、署名等で出典と内容を確認する。休場・個別銘柄停止、欠測、遅延、重複や順序逆転では、予測・約定・採点を進めない条件をテストする。
3. **接続と停止**。提供元の設定と API キーはサーバー管理とし、キーは専用の秘密情報保管先に置く。ブラウザから接続元・価格・許諾・稼働モードを設定できないようにする。利用期限の終了や検証失敗で接続を停止し、契約に沿って保存済みデータを削除できることを確認する。

## P9 身内向けリアル相場ゲームの構成案（2026-11-19、設計のみ）

Gemini Web版との設計レビュー後、公式のデータ利用条件も照合してまとめた案。**この章は実装・利用許可の完了を意味しない。** P8の `MOCK_NONLIVE` と `TEST_ONLY` の厳格な境界を維持する。開発は既存の `dev/forward-game` だけで行う。

### 開始方針

- **株式優先**。開発者本人の実株価フィード試験候補は Alpaca Basic の IEX リアルタイム米国株。IEXは全米取引の一部なので「全米の正式な株価」「全米リアルタイム統合値」と表示しない。対象銘柄で約定が無い場合は予測・採点を保留する。無料APIを取得できることと、友達に表示・採点結果を配信する許可は別問題。
- TradingView公式ウィジェットは許可範囲内で独立した**閲覧用**。ウィジェット内部の値を読み取って予測・採点・学習する経路を作らない。表示チャートの数値をゲームの約定価格と同一視しない。
- 暗号資産は24時間取引できる予備案。CoinGecko無料Demo APIに商用利用権は含まれない。暗号資産を採用する場合も当該データ源の公開・加工・保持・再配布の権利を別途確認する。
- **許諾未確認の招待制公開**では実市場由来の価格APIや自動採点を無効化し、友人には `MOCK_NONLIVE` の練習だけを開放する。友達5人でも第三者提供になる可能性がある。

### 部品を分離する（現在のコードに上乗せする設計）

1. **価格データの入口（MarketFeedAdapter）**：提供元APIで受けた価格を `symbol / venue / provider / tradeAt / publishedAt / receivedAt / price / sourceMode / conditions` に統一。API鍵はサーバーのみが保持し、ブラウザから接続先・価格・権限を指定させない。
2. **市場ルール（MarketSessionPolicy）**：地域別の取引時間・祝日・夏時間・時間外取引・約定区分を担当。プロバイダーの入れ替えと市場ルールの変更は別にテストする。
3. **検証と観測の記録**：価格>0、時刻逆行なし、予測時点で未公表のデータなし、適切な取引区分と鮮度、十分な約定数を確認。出典と受信時刻の証拠を添える。原データ保存は契約で許される範囲に限定する。
4. **Python予測→事前確定（Freeze）**：P7の保存済みモデルを使用。銘柄・時刻・予測確率・モデル版・使用データ版を将来価格が出る前に固定。後から更新しない。
5. **仮想決済と採点**：予測より後の適格な価格だけで損益と上昇/横ばい/下落の精度を算出。欠測・遅延・時間外は保留／無効扱いにし、架空値で埋めない。
6. **ゲーム内為替→専用財布**：確定損益のみ0.98〜1.02倍してメダルへ反映。予測確率・実価格・元本・的中率は絶対に補正しない。他AIの財布や未配分メダルに損失を移さず、借金・二重精算を拒否。
7. **画面**：外見作成と予測スタジオを分離したまま、データ出典と `架空練習 / 個人検証 / 許可済み実市場 / 未接続` を明示。成績は予測精度、元の仮想損益、FX込みメダル損益、最大下落率をそれぞれ別表示。

### 第一候補のゲームルール（仮決定、未検証）

- 最初は**米国株の通常取引時間のみ／60分先の上昇・横ばい・下落**で試験する。取引終了まで60分以上ないラウンドは開始しない。時刻は米国市場の夏時間・休場に対応する。日本時間で固定の市場時刻を作らない。
- 直近の連続した5分単位の価格履歴を必要数取得し、保存モデルの長期窓（現在既定9）の入力を満たさない場合は予測しない。IEXに約定が無い区間は無理に補完しない。
- 上昇／横ばい／下落のしきい値は**ラウンド開始前に固定**して履歴へ保存する。数値はバックテストを経て決める。新規銘柄・取引所で同じ値を無検証で使わない。
- 60分後の価格が指定した許容観測時間内に確保できなければ無効扱いとして参加メダルを返す。勝手に以前の終値を流用しない。これは初期案であり、採点品質を見て調整する。

### 独自為替の公平性

- ラウンド開始時にサーバー側で倍率を **0.98 / 0.99 / 1.00 / 1.01 / 1.02** から一度だけ選び、ラウンドIDと共に確定保存。予測締切前に選定の証拠（コミットメント）を記録し、締切後かつ結果判明前に倍率を公開して照合可能にする。再抽選禁止・参加者全員同倍率。
- `rawPnl`（実価格で計算した仮想損益）を先に確定し、`gamePnl = round(rawPnl × fx)` を記録する。プラスもマイナスも同じルールで補正し、損失が確保済み財布額を超える場合は許された最大損失で止め、他の財布から引かない。
- 予測スコア（Brier等）とメダル残高ランキングは別集計。為替の運ではAIの予測能力を高く評価しない。

### 実装順・検証条件

1. P9a：市場ルールと価格データの共通形式を **架空データのみ** で作り、未来情報の混入・時刻逆行・欠測・二重保存を自動テストする。
2. P9b：独自為替をサーバー側で確定→決済時だけ適用し、再起動・同じ取引の再送・資金上限・監査のテストを追加する。
3. P9c：架空データ用 FX ジャーナルに独立した監査アンカーと読み取り専用の決済表示を加える。実 IEX の受信・精度試験は権利確認後の別工程とする。
4. P9d：専用のローカル構成で架空 FX の監査済み結果を表示する。友人招待・認証・個別の支出用財布は別工程とする。

### Gemini再レビューから採用しない提案（安全性のため）

- Geminiは「翌営業日終値で判定」を提案したが、Alpaca Basic/IEXは全米の公式終値を保証しない。**公式終値の採点を実装済み・利用可能とみなさない**。将来、許諾済み公式終値フィードが得られた場合の日次モードとして別途設計する。個人試験の60分モードはIEX限定の定義を明記する。
- Geminiの「再起動時に期限切れ未確定予測を自動FROZENへ移行」は**不採用**。締切までにサーバーが正しく確定保存した証拠がない予測は失効／無効とする。後出し確定はしない。
- Geminiの「すべての財布に強制的な残高上限を適用」は**不採用**。既存の各AI専用財布の損失上限を守りつつ、利益を上限で突然没収しない。損失のための担保・投入額は注文時に確保し、残高を0未満にできない。

- ゲーム内FXを「予測終了後に事後決定」しない。ラウンド開始前の確定証拠を残し、締切後に公開・照合する（結果判明後の引き直し禁止）。

### P9b 実装済みの範囲

- サーバー内部の `openForwardGameFx` は P4 の読み取り専用 `recordSource` を使用する。専用のローカルジャーナル、全プロセス共通のサーバー鍵、口座に専有させる P4 財布ファイルと予測ディレクトリをサーバー設定で指定する。全口座が同一のジャーナルを共有し、銘柄・市場・対象時刻で識別したラウンドの倍率と署名付き参照を共通化する。
- `commitRound()` で対象時刻前に倍率のコミットメントを確定し、P4 のエントリー後に `reserve(forecastId)` で当該建玉の証拠金を確定する。P4 が対象時刻で決済・採点してから `settle(forecastId)` で倍率と照合用 nonce を返す。現行 P4 は予測受付の最終締切と対象時刻を共用しているため、倍率をその間に公開する運用は別の受付締切を設ける段階で対応する。
- 元の実現損益と FX 適用後の損益を別々に保存する。メダル単位に丸め、ちょうど半分は絶対値が大きくなる方向へ丸める。損失は確定済み証拠金までとし、`virtualProceeds` は投入証拠金と FX 後の損益の合計。二重書き込みを拒み、再送時は既存の決済を照合して返す。採点済みの旧レシートに後から FX を付与するには当時の事前確定記録が必要。
- 支出可能な残高の管理と画面への接続は今後の作業。P4 の予測・採点・財布への書き込みは既存処理が担当する。鍵を共有する信頼済みサーバーと専用ディレクトリを前提とし、ジャーナル全体の削除や巻き戻しの検知には別途保管・監査が必要。

### P9c 独立監査アンカーと決済の読み取り

- 新規の `MOCK_NONLIVE` 運用では、サーバー所有の空ディレクトリを二つ用意し、P4 ソースとともに `initializeForwardGameFxAudit` に明示して一度だけ初期化する。両ディレクトリは互いに独立し、P4 の予測・財布ディレクトリとも分離する。運用時は `openAnchoredForwardGameFx` に同じパスとサーバー鍵を渡す。従来の P9b ジャーナルは従来の API で扱い、後から監査済みとして取り込む処理は設けていない。
- 所有者、ラウンド、証拠金予約、締切確認、決済の各レコードに対し、独立ディレクトリに認証付きの内容ハッシュを先に公開・同期する。その公開に成功したプロセスだけが対応するジャーナルレコードを追記できる。双方のマニフェストと全レコードの対応を起動時と各操作で照合し、片側に残ったレコードの欠落や差し替えがあれば停止する。
- アンカー公開後にプロセスが停止して片側だけが残った場合は、書き込みと FX 読み取りを停止する。失われた側の同一レコードを独立バックアップから照合・復元できる場合だけ再開する。照合できる原本がなければ、そのジャーナルは停止したままとする。同じレコードの両側の削除や、両ディレクトリを同じ履歴へ巻き戻した場合はローカルの照合では検知できない。両方を一緒に失わない保管・バックアップが必要。
- `createForwardRecordReader` に同じ P4 ソースに結び付いた `fxSource` を明示した場合、表示項目 `fx` は採点済みの P4 結果と監査済み決済が一致するまで `null`。一致した後に `rawPnl`、`gamePnl`、`basisPoints`、`commitment` を返す。読み取り中の追記や同期処理はなく、nonce や口座・内部パスを含めない。既存の方向判定、Brier、的中判定、元の損益は従来の項目で返す。

### P9d ローカル画面への監査済み FX 表示

- `/game` の「保存したAI・模擬運用記録」を開き、記録と同じ AI・モデル版を選ぶと、監査済みの FX 決済を「ゲーム内為替（架空）」に表示する。元の仮想損益・FX倍率・FX後の仮想損益を、予測の採点や財布残高と分けて表示する。FX を有効にした構成で未決済の場合は「まだ監査済みFX決済なし」と表示する。
- 表示は、同じ P4 財布と対応する P9c の `fxSource` を `createGameServer` に明示した、単一アカウントの隔離ローカル構成で利用できる。既存の読み取り専用 GET を使い、既定の起動は実市場未接続のまま。ループバック・同一オリジンの制限とは別に、友人向けの公開にはアカウント認証と財布・記録への認可が必要。
- 支出用財布への反映は未実装。P4 は証拠金と元の実現損益を既に残高へ戻すため、FX 後の受取額をそのまま加えると元本を二重計上する。残高へ反映するには、P4 と FX の決済を一度だけ適用する会計処理が必要。

### P9e ローカル招待とアカウント別の模擬財布

- `startFriendMockServer({accounts, walletRoot})` を管理者のローカルコードから明示的に起動する。`accounts` は英数字の ID 2〜10件から、専用ルート下の個別ディレクトリに置いた絶対パスへの `Map`。専用ルートと個別ディレクトリは実行ユーザー所有の `0700`、既存の財布は同ユーザー所有の `0600` の通常ファイルでリンク数を1とする。これらを読み取り前後で照合する。財布が未作成の場合も個別ディレクトリは事前に作る。接続先は `127.0.0.1` に固定し、Host と POST の Origin は返された `http://friend.localhost:<port>` を使う。
- `issueInvite(accountId)` で発行した招待は1回限りで24時間有効。`POST /friend/invite/redeem` に JSON の `invite` を渡すと、`no-store` の JSON に8時間有効の `sessionToken` を返す。クライアントは揮発性メモリにだけ保持し、同じローカルオリジンに `Authorization: Bearer <token>` を明示して送る。Cookie、URL、ソースコード、ログ、ディスク、`localStorage` に保存しない。`GET /friend/session` の CSRF トークンは `POST /friend/logout` の `X-CSRF-Token` に使う。招待とセッションは再起動で失効する。引き換えの失敗が上限に達しても、有効な招待は受け付ける。
- `GET /friend/forward/summary` はセッションに対応する `MOCK_NONLIVE` 財布の要約だけを読み取る。財布、AI、口座を指定するクエリは受け付けない。通常のゲーム画面やモデル・外見・財布の更新 API とは分離する。
- P9e はローカル HTTP API の試験段階。ブラウザーでの操作は下記 P9h を参照。公開には HTTPS と `Secure` な `__Host-` Cookie を使うフロントエンド、永続的な認証情報の管理、モデル・外見・予測のアカウント別認可が必要。OS 上の財布ディレクトリは信頼済みの管理者だけが扱う。

### P9f 口座別キャラクターと模擬予測の読み取り

- `GET /friend/character` は、Bearer に対応する財布と同じディレクトリの `companion.json`（最大4 KiB）と `looks.json`（最大2 KiB）を読む。各ファイルは実行ユーザー所有・0600・リンク数1の通常ファイルに限る。応答の `companion` と `looks` にそれぞれ保存済みフラグ `created` と `revision` が付く。ファイルがない側は未保存の初期値となり、相棒が未保存なら `model_version` は null。破損・権限違反・読み取り中の差し替えを検出すると503を返す。
- `GET /friend/forward/records` は、管理者が起動時の任意設定 `accountRecordSources`（口座IDをキー、`{forecastId, source, fxSource?}` を値とする Map）で指定した1予測を返す。P4模擬ライフサイクルの `recordSource`、その口座の財布、財布と同じディレクトリ直下の専用 `forecasts/`（0700）が一致することが条件。該当口座が未設定なら `{"status":"unconnected","records":[]}`。設定済みの予測が見つからない場合や、必須の確認記録・保存済みの約定証拠を検証できない場合は503。任意のFX調整後損益は表示専用。
- 両GETはローカルの友人用API専用で、セッションから対象口座を選ぶ。レスポンスは `no-store`。キャラクターの保存、予測の生成、ブラウザーUI、外部公開はこの段階の対象外。

### P9g 認証済み口座の相棒・外見・戦略保存（ローカル試作）

- 新規POST `/friend/character/companion` は `{expected_revision,companion}` を受け、本人の `companion.json` のみ保存する。POST `/friend/character/look` は `{expected_revision,look}` を本人の `looks.json` のみ保存する。口座ID・ファイルパス・AI ID はHTTP入力として受け付けない。両方ともBearer認証・同一オリジン・`X-CSRF-Token` が必須で、読み取り系GETおよび既存のログアウト/招待経路は維持。
- 保存対象は実行ユーザー所有の0700ディレクトリ内にある0600の通常ファイルのみ。期待する更新番号が古い場合は409。複数サーバー同時実行では同じディレクトリの排他ロックで競合を検出し、書き込みは一時ファイル同期→名前置換→ディレクトリ同期で実施する。異常時に既存の不正リンクや他者のロックは削除しない。途中で強制終了してロックが残った場合は自動消去せず、管理者による確認が必要。
- 保存された相棒の判断ルールに基づき、GET `/friend/character` のモデル版が変わる。ただし保存操作は過去の確定予測・模擬決済・P4台帳・キャラクターの既存AIモデルを遡って変更しない。外見・戦略の編集は「次回以降の候補設定」であり、売買可能な新規モデルが自動で生成/登録されたわけではない。
- P9g はループバック `127.0.0.1` の読み取り・保存APIの試作段階。ブラウザーでの操作は下記 P9h を参照。公開にはHTTPS、権限・保存耐久性・操作履歴・ユーザー別画面の追加審査が必要。

### P9h ブラウザー相棒アトリエ（ローカル試作）

- 管理者が `startFriendMockServer` で専用の友人サーバーを起動し、`issueInvite(accountId)` で一度限りのコードを発行する。利用者は返された `origin` の末尾に `/friend/` を付けてブラウザーで開き、コードでログインする。接続は `127.0.0.1` と厳格な `friend.localhost:<port>` の組み合わせに限る。IPv6 が先に選ばれる環境の Chrome テストでは `--host-resolver-rules="MAP friend.localhost 127.0.0.1"` と `--no-proxy-server` を使う。
- 公開の静的 GET は `/friend/`、`/friend/editor.js`、`/friend/editor.css` の3経路。固定ファイル名、クエリなし、`no-store`、`no-referrer`、`nosniff`、同一オリジンのリソースポリシーと HTML 専用 CSP を適用する。プロフィール・財布・予測記録は既存の認証付き経路から読み取る。
- 名前・髪色・服の色・予測スタイル・リスク配分は「相棒と戦略を保存」、髪型・表情・アクセサリーは「外見パーツを保存」で本人の口座に保存する。ちび相棒のプレビューは入力時に更新する。保存版は独立して管理し、競合時はサーバーの最新設定を読み込んで再入力を案内する。戦略の変更は次回以降の予測候補設定に反映する。
- 財布の未配分・初期メダル、模擬予測の採点状態と確定予測のモデル版を読み取り専用で表示する。財布の未作成、予測の未接続、取得エラーは個別に表示し、確定予測のモデル版は編集設定のモデル版と区別する。対象は `MOCK_NONLIVE` のみ。実株価、実口座、取引や出金に使えるFX残高は扱わない。
- Bearer と CSRF はページのメモリーに保持する。401、ログアウト操作、ページ離脱時は表示とセッションを消去し、処理中だった応答の反映を止める。ログアウト通知に失敗した場合は画面を消去したうえで通知結果を表示する。招待メール、外部公開、実環境への配備は対象外。

回帰テストは `node --test mcp/tests/friend-mock-auth.test.mjs mcp/tests/friend-mock-ui.test.mjs`。Playwright が既にある環境では Chromium の操作テストも実行できる。必要に応じて `FRIEND_UI_PLAYWRIGHT` に Playwright のモジュールファイル、`FRIEND_UI_CHROME` に Chrome の実行ファイルを設定する。テストは一時ディレクトリとランダムなローカルポートを使う。
