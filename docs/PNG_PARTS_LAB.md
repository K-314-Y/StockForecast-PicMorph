# PNGパーツ実験室（Sprint 83）

実行画面：ゲームの「外見からキャラを作る」→「私のイラストを重ねる」→「PNGパーツ実験室を開く」、または同じローカルサーバーの /parts-lab/preview.html。

## この実験でできること

- 自作、または改変・利用許可のあるPNG/WebPを**ブラウザだけ**で合成する
- 必須：顔の描かれていない体と、背景透明の通常顔
- 任意：うれしい顔、しんぱい顔、前髪、服
- レイヤーの重ね順：体→服→顔→前髪
- 1コマを緩やかに動かす、または横並び6コマを指定速度で再生する
- 表情切替、体・服・顔・前髪の位置調整、一時停止
- 自作素材がまだない場合は、Creature Lab独自デモから派生させた固定WebP 4点を明示的に読み込んで試せる

素材は同一サイズの**キャンバス全体**で書き出す。6コマの場合は6枚を横一列に連結した画像を、体と各表情のすべてに使用する。1コマの縦横は32〜1024px。ファイルはそれぞれ最大5MB。顔・前髪・服は背景を透明にする。通常顔以外の表情を省いたときは通常顔を再利用する。

「動かすパーツ」で読み込み済みのレイヤーを選び、プレビュー上でそのレイヤーの絵がある部分をマウスや指でドラッグする。別のパーツが重なっていても、選んだレイヤーをつかめる。6コマ素材は表示中のコマで判定し、位置は全コマで共通。顔はどの表情にも同じ位置調整を適用する。

横・縦位置は数値欄でも1px単位で調整できる。顔は従来どおり±24px、体・服・前髪は1コマの短辺の半分（端数切り捨て、最大128px）まで。コマの外にはみ出た部分は切れる。「選んだパーツの位置を戻す」でそのパーツを初期位置に戻せる。素材を新しく読み込むと位置は初期化される。位置調整は表示と保存する立ち絵に反映され、予測モデルには影響しない。

## ZIPキャラのアクセサリー

ZIPのコマ数を選んでからZIPを読み込む。既定は従来の横並び6コマ。装備したアクセサリー（最大3個）ごとに、表示用の静止PNG/WebPを任意で選べる。重ね絵なしでも分析装備を登録でき、「重ね絵だけ外す」を押しても分析装備は有効。

重ね絵は5MB以下、縦横1〜1024pxで、透明またはほぼ透明な画素が1割以上あり、見える絵が必要。プレビューでは前髪の上に装備順で重ねる。横・縦位置は中央を0%、移動できる両端を±100%とし、拡大率は25〜200%。絵全体がコマの中に収まるよう制限する。各コマで位置と大きさは一定で、キャラの動きに追従させる処理は行わない。

「動かすパーツ」の既定値は「アクセサリー」。プレビュー上で重ね絵の見える部分をマウスや指でドラッグすると、横・縦位置の数値欄も更新する。重なった部分では、触れた位置で見えている最前面の重ね絵を動かす。数値欄はキーボードでも調整できる。1コマのプレビューは編集中は上下に揺れ、ドラッグ中はその場で止まる。ドラッグできる間は、プレビューの外側からページをスクロールできる。

明示的に登録すると、プレビューの最初のコマを12日間の練習で使う立ち絵として保存する。同じ登録ファイルに選択した表情、レイヤーごとの位置、添付した重ね絵の元ファイル・位置・拡大率も保存する。

## 登録済みZIPキャラの見た目の再編集

上部の「登録済みZIPキャラの見た目を編集」からキャラを選び、「見た目を編集」を押す。最後に保存した表情・位置・重ね絵からプレビューを組み直す。体と顔の位置、利用できる表情、重ね絵の位置や大きさを調整できる。ZIPから読み込める素材は体と表情なので、手動プレビュー用の服・前髪はここでは編集できない。「見た目の変更を保存」で確認を確定すると、同じキャラIDの立ち絵と再編集用の情報をまとめて保存する。

以前の形式で登録したキャラは、保存されている体と通常の顔を初期位置で読み込む。以前の立ち絵に焼き込まれた表情、位置、重ね絵の元ファイルは復元できない。残したい重ね絵を添付して保存すると、次回からその編集内容を開ける。

見た目を変更して保存すると、直前の立ち絵と編集情報が1件だけ残る。「1つ前の見た目に戻す」を押し、確認画面で「1つ前に戻す」を選ぶと、その立ち絵と編集情報に戻る。編集中の変更は破棄される。復元後にもう一度押すと、復元する直前の見た目に切り替わる。編集情報がない版に戻した場合、保存済みの立ち絵が戻り、プレビューには元の素材を初期位置で表示する。見た目の保存・復元では、キャラID、元の体・表情素材、予測モデルや装備設定を保持する。

`GET /api/imported-characters/visual-edit/:id` は `can_restore_previous` と `edit_token` を返す。編集情報付きの保存と `POST /api/imported-characters/visual-edit/:id/restore` は、`expected_image_sha256` と `expected_edit_token` を照合する。立ち絵が同じでも位置などの編集情報が変わっていれば、古い画面からの保存・復元は409になる。立ち絵だけを更新する旧クライアントは、画像のSHA-256だけで保存でき、最後に保存した編集情報を引き継ぐ。見た目に変更がない保存では履歴を更新しない。

## 実装・プライバシー

実験室は /parts-lab/preview.html と固定許可リストにあるスクリプトを配信する。ローカル素材はファイル入力とブラウザの createImageBitmap() で読み取り、canvasの drawImage() で合成する。画像はZIPキャラの新規登録、見た目の再編集保存、1つ前の見た目への復元を確定したときに、このPCへ保存する。画像のAI認識や生成、外部サービスへの送信は行わない。

デモボタンを押した場合だけ、ゲーム内の固定画像4点を同じローカルサーバーから取得する。画像はページを閉じるか解除すると ImageBitmap.close() で解放する。prefers-reduced-motion 指定時は静止画像を表示。サーバー側は Content Security Policy、no-store、nosniff、X-Frame-Options DENY を適用する。ユーザーの元画像と登録時の体・表情素材は保持する。

登録リクエストとキャラごとのJSONは各50 MiB、見た目の再編集リクエストは22 MiBまで。ZIP由来の素材は各5 MiB、立ち絵は1 MiB、合わせて21 MiBまで。重ね絵は最大3点で各5 MiB、計15 MiBまで。再編集のGETは現在の元素材と重ね絵をBase64で返す。再編集用の情報は登録ファイルの任意フィールド `visual`（`schema: 1`）に保存し、履歴は `previous_visual` に立ち絵と任意の `visual` を1件保存する。履歴を含めたJSONが50 MiBを超える保存は413になり、保存済みの見た目と履歴は保持される。

## 未実装・限界

- 顔のない体画像を**自動生成・自動分割する機能ではない**。元絵に顔が描かれていると二重になる
- 1枚の静止画を使った場合、揺れるのは全体であってLive2Dのように関節や髪を個別変形できない
- 6コマの顔を固定1枚で流用する方式は実装していない（コマ位置がずれるため）
- 画風やキャラが著作権上安全であることの自動判定はできない。他人の素材を少し加工しただけでは許可にならない
